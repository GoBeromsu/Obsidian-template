Related: [Start (English)](../../README.md) · [시작 (한국어)](../../README.ko.md) · [Templates](../02%20Templates/README.md) · [템플릿](../02%20Templates/README.ko.md) · [Writing and AI](02.%20Writing%20and%20AI.md) · [글쓰기와 AI](02.%20Writing%20and%20AI.ko.md) · [Templates agent contract](../02%20Templates/AGENTS.md)

Every note has exactly one canonical location. Choose that location by what the note *is*, not by who wrote it, which language it is written in, which tool captured it, or where you first thought of it. A Korean note and an English note of the same kind share that same folder. When two folders seem plausible, apply the precedence rules below instead of duplicating the note.

Knowing where a note belongs is not permission to edit it. Placement answers *which folder*. Edit permission follows the adopter's local policy and exact-note authorization. Root presence does not grant write access.

## Ten roots (public subset)

This vault ships **ten roots**. That is a deliberate public subset of a 12-root policy: publication (`25. Digital Garden`) and faith (`60. Saint`) are excluded. Do not add, rename, or renumber roots. Do not add a Handbook folder, private integrations, or extra private-vault subfolders in order to place a note. This template does not move notes for you.

Do not copy a personal metadata schema or private folder tree into this template.

## Decision list

File a note by walking this list in order and stopping at the first match.

- Unsorted capture → `00. Inbox`
- Periodic planning or review (daily, weekly, monthly, quarterly, yearly, dashboard) → `10. Time`
- Work with an end condition → `15. Work/01 Project`
- Ongoing responsibility → `15. Work/02 Area`
- Inactive project or area the user has **decided** to archive → `15. Work/03 Archive`
- Standalone tasks with no owning project or area → `15. Work/04 Tasks`
- Thinking derived from an external source → `30. Literature Notes`
- Self-contained idea or principle → `40. Permanent Notes`
- AI-generated or AI-synthesized content with no owning project → `50. AI`
- Reusable catalogs of people, prompts, MOCs, music, places, organizations, GitHub, or channels → `70. Collections`
- Books, papers, attachments → `80. References`
- Captured external originals, regardless of who captured them → `85. Raw`
- Vault and system settings, rules, templates, Excalidraw drawings and assets → `90. Settings`

Excalidraw drawings and assets belong in `90. Settings/07 Excalidraw`. This template does not install the Excalidraw plugin; a bundled `data.json` is path config, not plugin binaries.

Raw subfolders describe content, not vendors: `01 Articles`, `02 Videos`, `03 Clippings`, `04 Discussions`, and `05 Newsletters`. Discussions include forum threads, social conversations, and other discussion transcripts from any service; record the source URL in the note.

## Source versus interpretation

Keep the captured original apart from what you make of it. One note is not both.

- The external original (clip, transcript, article file, URL capture) stays in `85. Raw`.
- Your interpretation of that source (research, review, meeting note derived from it) lives in `30. Literature Notes`.
- A self-contained idea that no longer depends on one source lives in `40. Permanent Notes`.
- Bibliographic wrappers (book, paper, attachment) live in `80. References`; they are not a substitute for the Raw original or the literature note.

Do not duplicate the same note across those roots. Link them.

## Root worksheet (`Me.md`)

`Me.md` at the vault root is a shipped bilingual starter worksheet and the single deliberate root-level note exception: it is the lecture entry point, so it sits beside `README.md` instead of inside a numbered root. It has four `###` sections (Summary Statement, First Principles, How I Think, Working Preferences) plus `## Thinking`, each answer area with Korean guidance. It is not a second home for identity notes and does not license other loose notes at the root. Fill it, then link related existing notes from your own Map of Content (MOC) in `70. Collections/03 MoC`, with a short reason for each link. Do not keep duplicated language copies of `Me.md`. It stays the single canonical `Me` note at the root; do not file a second `Me`/`me` note elsewhere.

## Projects, logs, and tasks

Start with this simple pattern; add supporting subfolders only when the work needs them.

- **Hub:** `15. Work/01 Project/<Name>/<Name>.md` with `type: project` (example: `15. Work/01 Project/Example Project/Example Project.md`).
- **Log:** `YYYY-MM-DD <topic>.md` next to that work, with `type: log` (example: `15. Work/01 Project/Example Project/2026-01-15 kickoff.md`).
- **Project-owned tasks** sit next to the work in that project (or area) folder. Use the task fields from [Templates](../02%20Templates/README.md) (`type: task`, `done`, `gtd`, `project`, `plan`, `due`).
- **Unowned tasks** — no project or area — go in `15. Work/04 Tasks`.

Completed tasks **stay put**. Mark them done in place. Completing a task is not a reason to move it to Archive.

Archive an inactive **project or area** only by a deliberate user decision: move that project or area into `15. Work/03 Archive`. Agents and this template do not auto-archive on completion, inactivity, or “finished work.” `15. Work/03 Archive` is not a dump for completed tasks.

## Time notes

Periodic notes live under `10. Time`. Folder numbers are not the hierarchy. The planning hierarchy is Year → Quarter → Month → Week → Day.

| Period | Folder | Title format | Example |
| --- | --- | --- | --- |
| Year | `10. Time/04 Yearly Notes` | `YYYY` | `2026` |
| Quarter | `10. Time/05 Quarterly Notes` | `YYYY-Qn` | `2026-Q1` |
| Month | `10. Time/03 Monthly Notes` | `YYYY-MM` | `2026-09` |
| Week | `10. Time/02 Weekly Notes` | ISO week year `GGGG-WW` plus `W` | `2026-37W` |
| Day | `10. Time/01 Daily Notes` | `YYYY-MM-DD` | `2026-09-11` |
| Dashboard | `10. Time/06 Dashboard` | `YYYY-MM-DD Dashboard` | `2026-09-11 Dashboard` |

Weeks are ISO weeks (Monday–Sunday). Do not use a Sunday-start week, and do not treat Sunday as belonging to the next week. Wikilinks between periods (`year`, `quarter`, `month`, `week`, previous/next, dashboard `up`) are navigation only; they do not create the target note. Creating a daily note may create missing dashboards for yesterday, today, and tomorrow; it does not create the week, month, quarter, or year note. Template paths, the daily dashboard hook, and task fields are in [Templates](../02%20Templates/README.md).

## Precedence

Folder is about ownership and kind; metadata is about the writer and the capture path. Language does not get its own tree.

- Content produced inside a specific project belongs to that project even when an AI wrote it. Distinguish the writer with an `authorship` field, not by folder. Do not add extra metadata fields beyond what the adopter already uses, and do not copy a personal metadata schema into this template. Human templates in this vault stamp `created_by: user` and `authorship: user`.
- A captured original belongs in `85. Raw` even if an automated pipeline captured it. Collector and language do not change that folder.
- Completed tasks stay in their current project, area, or task path. Record completion on the note; do not move it. Archiving a project or area is a separate, deliberate user decision (see above).

Writing, metadata field policy, and AI safety: [Writing and AI](02.%20Writing%20and%20AI.md) · [글쓰기와 AI](02.%20Writing%20and%20AI.ko.md).

## Publication

A refined publication version is a separate note from the originating thinking note, not a copy of it. This public template has no publication root. If you later add one, record the root decision in both language files of this guide, and keep the thinking note in its original location.

## Not included

This template ships structure and rules, not a personal life.

- No faith root (`60. Saint`)
- No publication root (`25. Digital Garden`)
- No Handbook folder
- No external tool integrations or private integrations
- No personal data
- No installed community plugins or theme binaries (plugin ID lists, bundled `data.json`, and `cssTheme: Minimal` are not installations)
- No private metadata schema or private-vault subfolders
