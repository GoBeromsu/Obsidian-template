# 에이전트 스킬

[English](03.%20Agent%20Skills.md) · [한국어](03.%20Agent%20Skills.ko.md)

[시작](../../README.ko.md) · [배치](01.%20Placement%20Guide.ko.md) · [글쓰기와 AI](02.%20Writing%20and%20AI.ko.md) · [템플릿](../02%20Templates/README.ko.md)

이 볼트는 에이전트 스킬 하나를 함께 제공합니다: [GoBeromsu/craft-skills](https://github.com/GoBeromsu/craft-skills)의 `obsidian`입니다. 스킬은 `SKILL.md`를 담은 폴더이며, 에이전트는 작업 내용이 설명과 맞을 때만 이를 불러옵니다. 이 스킬은 `.base` 쿼리, `.canvas` 그래프, Mermaid 블록, Web Clipper 템플릿이 실제로 어떻게 동작하는지 에이전트에게 알려줍니다 — 추측하게 두는 대신입니다.

스킬은 프로그램이 아니라 지시문입니다. 이 폴더가 있다고 해서 무언가가 실행되거나 설치되거나 외부로 신호를 보내지 않습니다. 출처와 갱신 절차는 [`.agents/skills/README.md`](../../.agents/skills/README.md)에 있습니다.

## 어디에 있는가

세 런타임은 발견 경로를 하나로 통일하지 않으므로, 볼트는 스킬을 한 벌만 담고 두 경로로 노출합니다.

| 경로 | 읽는 런타임 | 종류 |
| --- | --- | --- |
| `.agents/skills/obsidian/` | Codex, Antigravity | 실제 디렉터리 — 유일한 원본 |
| `.claude/skills/obsidian` | Claude Code | 위 디렉터리를 가리키는 심볼릭 링크 |

내용의 원본은 하나뿐입니다. Claude Code는 `.claude/skills/`만 읽지만 심볼릭 링크로 연결된 스킬 폴더는 따라갑니다. Codex와 Antigravity는 둘 다 `.agents/skills/`를 스캔하는데, Antigravity의 스캐너는 심볼릭 링크를 무시하므로 그 경로가 실제 디렉터리여야 합니다. 어느 경로를 편집해도 같은 파일을 편집하는 것입니다.

## 사용하기

볼트 폴더를 작업 공간으로 열고, 볼트 루트에서 에이전트를 시작합니다. 각 도구는 스스로 스킬을 발견하고 요청 내용이 맞을 때 불러옵니다 — 평범한 말로 물어보거나 스킬 이름을 직접 언급하면 됩니다:

```text
Use the obsidian skill: build a Base that lists every note in 15. Work with status todo
```

| 런타임 | 설정 | 확인 방법 |
| --- | --- | --- |
| Claude Code | 불필요; 볼트 루트에서 `.claude/skills/`를 읽음 | `/skills` |
| Codex | 불필요; 볼트 루트에서 `.agents/skills/`를 스캔 | 어떤 스킬이 있는지 물어보기 |
| Antigravity | 불필요; 작업 공간 루트에서 `.agents/skills/`를 스캔 | 스킬을 추가한 뒤 세션을 재시작하고, 어떤 스킬이 있는지 물어보기 |

Codex와 Claude Code는 upstream 전체 라이브러리를 담는 네이티브 플러그인 설치도 지원합니다. 이 볼트의 스킬 하나가 아니라 한 기기에서 30개 스킬 전부를 쓰고 싶다면 그쪽이 더 나은 경로입니다. 해당 명령은 upstream의 README에 있습니다.

## 스킬이 보이지 않을 때

하위 폴더가 아니라 볼트 루트에서 에이전트를 시작합니다: 세 런타임 모두 작업 디렉터리에서 위로 거슬러 올라가며 찾으므로, 다른 곳에서 시작한 세션은 이 폴더들에 닿지 못할 수 있습니다. 스킬을 추가하거나 옮긴 뒤에는 세션을 재시작합니다. 그다음 두 경로가 모두 정상인지 확인합니다:

```sh
cat ".agents/skills/obsidian/SKILL.md" | head -3
cat ".claude/skills/obsidian/SKILL.md" | head -3
```

두 번째 명령만 실패하고 첫 번째는 성공한다면 압축 해제 과정에서 심볼릭 링크가 살아남지 못한 것입니다 — 일부 Windows ZIP 압축 해제 도구는 심볼릭 링크 대신 자리표시용 텍스트 파일을 씁니다. 볼트 루트에서 다시 만듭니다:

```sh
rm -rf .claude/skills/obsidian
mkdir -p .claude/skills
ln -s ../../.agents/skills/obsidian .claude/skills/obsidian
```

심볼릭 링크 권한이 없는 Windows 환경에서는 폴더를 대신 복사하고(`cp -R`), 스킬이 갱신될 때마다 다시 복사합니다.

## 경계

이 스킬은 재사용 가능한 Obsidian 메커니즘을 담당합니다. 이 볼트의 결정은 스킬의 영역이 아닙니다: 노트가 어디에 속하는지는 [`01. Placement Guide.md`](01.%20Placement%20Guide.md)가, 글쓰기와 속성은 [`02. Writing and AI.md`](02.%20Writing%20and%20AI.md)가, 권한은 [`AGENTS.md`](../../AGENTS.md)가 맡습니다. 스킬의 일반적인 조언이 이 가이드들과 충돌하면 볼트의 가이드가 우선합니다.

CLI와 Sync 레시피는 이 템플릿이 함께 제공하지 않는 도구 — `obsidian-cli`, `ob`, 그리고 자신의 볼트를 가리키는 `OBSIDIAN_VAULT_PATH` — 를 필요로 합니다. Markdown, Bases, Canvas, Mermaid 레시피는 이런 도구가 전혀 필요 없습니다. 없는 도구를 요구하는 스킬은 명령을 지어내지 말고 그 사실을 보고해야 합니다.
