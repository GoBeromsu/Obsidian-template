# Writing and AI

[English](02.%20Writing%20and%20AI.md) · [한국어](02.%20Writing%20and%20AI.ko.md)

[Start](../../README.md) · [Placement](01.%20Placement%20Guide.md) · [Templates](../02%20Templates/README.md) · [Me worksheet](../../Me.md)

This is a small public writing and AI collaboration contract, not a copy of a personal vault's schema or automation. Placement owns where notes live; this guide owns writing, minimal properties, and AI boundaries; Templates owns engine setup. Applicable `AGENTS.md` contracts still apply.

[`Me.md`](../../Me.md) holds user context: who you are, your principles, how you think, your working preferences, and who influences you. `AGENTS.md` files hold repository rules for agents; they remain the source of truth for what agents may do. [`CLAUDE.md`](../../CLAUDE.md) at the vault root is only a pointer to both [`Me.md`](../../Me.md) and [`AGENTS.md`](../../AGENTS.md): agents read root `Me.md` first for user context, then follow `AGENTS.md` for repository rules. Being read first, for context, is separate from being an authorization: reading `Me.md` tells an agent about you, it does not grant edit permission on its own.

## Beginner syntax

Notes are ordinary Markdown. [`Me.md`](../../Me.md) at the vault root is a fill-in worksheet, not a program the vault runs.

Type in **editing** view; **reading** view shows the rendered note. Toggle them from the note menu (three dots on the open note).

Put a space after `#`, `##`, and `-`. For a checkbox, type `- [ ] ` with a space inside the brackets and after `]`. Here is a tiny note you can copy:

```markdown
# Practice title
## A section
- a bullet
- [ ] a checkbox
See [[Me]]
Make one word **bold**
```

`#` is the title in the note body, `##` a section heading, `-` a bullet, and `- [ ]` an unchecked task. `[[note name]]` links to another note: `[[Me]]` points to the existing worksheet. `**bold**` adds emphasis.

## Write for the next reader

Use a descriptive title, then `##` sections with no skipped heading levels. A useful flow is context → observation → interpretation → next action, not a mandatory form for every note.

Keep one idea per paragraph. Use numbered lists for sequences, bullets for actions, and tables for genuine comparisons. Do not turn every sentence into a heading. Use bold sparingly for decisions or warnings.

Separate actual quotations, your interpretation, and your decision. Preserve quoted wording and put a source link beside it; add a page, section, or timestamp when available. Label translations and AI drafts. Never invent a quote or make an unverified claim look sourced. Keep captured originals unchanged in `85. Raw`; write interpretation in a separate note.

Use `[[Me]]` for an internal connection after your context note exists, and Markdown links for external sources. Add a path only to disambiguate. A wikilink does not create, read, or authorize editing its target. GitHub does not render Obsidian wikilinks as navigation, so entry guides also use relative Markdown links. Use language-labelled code fences, such as `text`.

## Keep properties small and honest

Reuse the fields in the shipped templates; do not import a large personal schema. Keys use `snake_case`; dates such as `date_created`, `plan`, and `due` use plain `YYYY-MM-DD`, not wikilinks. Quote YAML wikilinks; a project's task link can be `project: ["[[Sample Project]]"]` after that hub exists. Tags are optional here: use a few consistent lowercase kebab-case tags, not a second folder tree.

- `created_by: user|agent` records who created the note; preserve the existing value.
- `authorship: user|agent|mixed` records writing contribution, not factual correctness. Reviewing AI text does not make it human-only.
- Human-facing templates intentionally start with `created_by: user` and `authorship: user`. When AI-written content is incorporated into a human-created note, preserve `created_by: user` and use `authorship: mixed`.
- New AI-authored notes use `created_by: agent` and `authorship: agent`. The shipped `Me.md` scaffold is agent-authored; when you add your answers to that same file, retain its creator and use `authorship: mixed`.
- Do not rewrite legacy provenance or plugin-managed fields to tidy them up. Missing provenance is not edit permission.

A hub uses `type: project`; a dated activity note uses `type: log`. Task notes retain the existing `done`, `gtd`, `project`, `plan`, and `due` contract; do not introduce a competing task status field. See the [template guide](../02%20Templates/README.md).

## AI may assist, not impersonate

For this beginner exercise, AI may ask questions, identify gaps, suggest an outline, or draft alternatives from the excerpts you choose to share. You decide what becomes a note.

AI must not invent your biography, preferences, evidence, achievements, or decisions. It must not overwrite another writer's note, change `## Thinking`, delete or move files, or publish material merely because it can access a folder. Existing-note edits need the exact note and scope authorized for the current task. A folder name, a link, or prior AI contribution is not ongoing permission.

`## Thinking` is human-only. Leave its contents out of the interview; save reviewed AI suggestions in a different section. These are behavioral rules, not installed technical guards.

## Gemini interview: three questions, then review

1. Fill the [Me worksheet](../../Me.md) locally with short answers. Unknown is a valid answer. Use generic examples in a class or public demo.
2. Remove personal identifiers, credentials, private work, other people's information, and `Thinking` before sharing. Paste only the necessary excerpt into Gemini, not the whole vault. Check the service's current privacy settings and your organization's policy first.
3. Paste this prompt with the excerpt:

   ```text
   This is a partial context note, not permission to access or edit my files.
   Ask exactly three clarifying questions about the most important gaps in my goal,
   audience, outputs, constraints, or success criteria. Do not invent answers.
   Wait for my replies. Then propose a concise update using my existing ## headings.
   Separate confirmed answers, suggestions, and unresolved questions.
   Do not write or rewrite ## Thinking. Do not claim anything was saved.
   ```

4. Answer the three questions. Review the proposed update line by line, correct errors, and discard unsupported claims. Save only accepted answers into the relevant sections of your local `Me.md`; keep unresolved issues in a note of your choosing. Record AI contribution with the properties above. Gemini web chat has no automatic vault access or save capability in this template.
5. Build your own Map of Content (MOC) in `70. Collections/03 MoC`: choose existing notes related to what you wrote in `Me.md` and link each with a short reason `[[Me]]` connects to. This is a human-curated table of contents you maintain yourself, not a generated project hub or context map.

**Done means:** you can explain your purpose and thinking from `Me.md`, and open a MOC note that links related context with reasons. No plugin or AI integration is required for this plain Markdown exercise.

## Before sharing publicly

Keep the filled worksheet and project notes in your own vault, not in a contribution to this template. Review filenames, text, properties, links, attachments, screenshots, and Git history before publishing. Deleting a secret from the latest file does not remove it from history. Do not assume a private-looking folder is excluded from Git or from an AI upload.
