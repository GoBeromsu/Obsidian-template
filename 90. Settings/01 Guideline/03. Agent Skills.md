# Agent Skills

[English](03.%20Agent%20Skills.md) · [한국어](03.%20Agent%20Skills.ko.md)

[Start](../../README.md) · [Placement](01.%20Placement%20Guide.md) · [Writing and AI](02.%20Writing%20and%20AI.md) · [Templates](../02%20Templates/README.md)

This vault ships one Agent Skill: `obsidian`, from [GoBeromsu/craft-skills](https://github.com/GoBeromsu/craft-skills). A skill is a folder with a `SKILL.md` that an agent loads only when the work matches its description. It teaches an agent Obsidian's actual mechanics — how a `.base` query, a `.canvas` graph, a Mermaid block, or a Web Clipper template really behaves — instead of letting it guess.

Skills are instructions, not programs. Nothing runs, installs, or phones home because this folder exists. Provenance and the update procedure are in [`.agents/skills/README.md`](../../.agents/skills/README.md).

## Where it lives

The three runtimes do not agree on one discovery path, so the vault ships the skill once and exposes it twice.

| Path | Read by | Kind |
| --- | --- | --- |
| `.agents/skills/obsidian/` | Codex, Antigravity | Real directory — the one copy |
| `.claude/skills/obsidian` | Claude Code | Symlink to the directory above |

There is a single copy of the content. Claude Code reads only `.claude/skills/` but follows a symlinked skill folder; Codex and Antigravity both scan `.agents/skills/`, and Antigravity's scanner ignores symlinks, so that path must be the real directory. Editing either path edits the same files.

## Using it

Open the vault folder as the workspace, then start the agent from the vault root. Each tool discovers the skill on its own and loads it when your request matches — ask in plain language, or name the skill:

```text
Use the obsidian skill: build a Base that lists every note in 15. Work with status todo
```

| Runtime | Setup | Check |
| --- | --- | --- |
| Claude Code | None; reads `.claude/skills/` from the vault root | `/skills` |
| Codex | None; scans `.agents/skills/` from the vault root | Ask which skills are available |
| Antigravity | None; scans `.agents/skills/` in the workspace root | Restart the session after adding skills, then ask which are available |

Codex and Claude Code also offer native plugin installs for the full upstream library, which is the better route if you want all 30 skills on a machine rather than this one skill in this vault. Upstream's README documents those commands.

## If the skill does not appear

Start the agent from the vault root, not a subfolder: all three walk upward from the working directory, so a session started elsewhere may never reach these folders. Restart the session after adding or moving a skill. Then confirm both paths resolve:

```sh
cat ".agents/skills/obsidian/SKILL.md" | head -3
cat ".claude/skills/obsidian/SKILL.md" | head -3
```

If the second fails but the first works, the symlink did not survive extraction — some Windows ZIP extractors write a placeholder text file instead. Recreate it from the vault root:

```sh
rm -rf .claude/skills/obsidian
mkdir -p .claude/skills
ln -s ../../.agents/skills/obsidian .claude/skills/obsidian
```

On Windows without symlink permission, copy the folder instead (`cp -R`), and re-copy it whenever the skill is updated.

## Boundaries

The skill owns reusable Obsidian mechanics. It does not own this vault's decisions: where a note belongs stays with [`01. Placement Guide.md`](01.%20Placement%20Guide.md), writing and properties with [`02. Writing and AI.md`](02.%20Writing%20and%20AI.md), and permissions with [`AGENTS.md`](../../AGENTS.md). When the skill's generic advice conflicts with those guides, the vault's guides win.

Its CLI and Sync recipes expect tools this template does not ship — `obsidian-cli`, `ob`, and an `OBSIDIAN_VAULT_PATH` pointing at your own vault. The Markdown, Bases, Canvas, and Mermaid recipes need none of them. A skill that asks for a missing tool should report it, not invent a command.
